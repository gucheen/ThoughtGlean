# 拾念对话提炼与复用改版方案

## 方案结论

这次改版不再以“给大量记录建立主题”为核心，而是解决信息进入记录库之前的问题：

> 将一段 AI 对话或外部材料，转换为少量、独立、可检索、可执行并且可信度明确的记录。

产品主流程调整为：

```text
对话或材料
    ↓
识别未来可能再次遇到的问题
    ↓
拆成独立的操作、结论、决策或故障记录
    ↓
用户检查命令、环境、风险和未知项
    ↓
保存为“未实际验证”的可复用记录
    ↓
真实使用后补充验证环境和结果
```

主题仍然有价值，但它只是后续的浏览入口。第一优先级是减少无效保存，让默认搜索面对的是提炼后的内容，而不是大量原始对话。

## 问题定义

典型场景如下：

1. 用户与 AI 讨论服务器管理问题；
2. 对话中出现解释、排查过程、多个方案和若干命令；
3. 用户担心以后忘记，于是保存完整对话；
4. 几个月后需要再次操作，只记得“Docker 磁盘”“证书续期”或半条命令；
5. 搜索命中很长的对话，用户仍需重新阅读并判断哪条命令适用。

问题不是缺少文件夹，而是保存单位错误：用户保存了“发生过的一次对话”，实际需要的是“未来可以独立完成的一次操作”。

## 与拾念定位的关系

AI 回答属于“外界说过什么”，不能在提炼后被呈现成用户自己的原话。此次改版不改变拾念以个人记录为主体的定位，而是增加一个清楚的来源边界：

- 原始 AI 对话作为素材或外部来源，不进入普通想法时间流；
- 提炼记录明确标出哪些命令和结论来自外部；
- 用户实际使用后的环境、结果和修正属于用户自己的记录；
- 如果未来与拾页连接，完整外部材料可以由拾页保存，拾念只保留提炼记录、引用片段和来源关系。

因此，产品保存的不是“AI 说过的话变成了我的知识”，而是“我准备在什么条件下使用这段外部信息，以及我后来是否验证过它”。

## 产品目标

- 用户不必把整段对话作为普通记录保存。
- 一次对话可以提炼为零条、一条或多条独立记录。
- 转换结果围绕未来使用场景，而不是复述对话过程。
- 命令、配置、错误原文和适用环境得到保留。
- AI 建议与用户实际验证具有明确区别。
- 原始来源可追溯，但不会淹没默认时间流和搜索结果。
- 无 AI、AI 失败或离线时，基础记录与手工提炼仍然可用。
- 转换过程遵循现有的离线、同步、冲突、备份和导出承诺。

## 非目标

- 不把拾念做成完整的对话归档服务。
- 不默认保存每一段 AI 对话。
- 不自动执行提炼出的命令或配置。
- 不自动把 AI 建议标记为可靠或已验证。
- 不要求普通想法使用固定模板或内容类型。
- 不引入必须维护的收件箱、未整理数量或知识库健康分。
- 不以复杂主题规则、标签体系或知识图谱作为本次改版前提。

## 核心原则

### 对话是素材，不是默认记录

原始对话用于追溯来源。默认进入时间流和搜索的主体，应是用户以后真正会寻找的记录。

### 转换不是摘要

摘要回答“这次聊了什么”，提炼回答“以后遇到什么问题时，我能直接使用什么”。提炼必须允许舍弃没有复用价值的内容。

### 按未来检索意图拆分

一条记录对应一个可以独立出现的未来问题。可以分别使用的操作必须拆开；只有必须连续执行才能完成目标的步骤才保留在一起。

### 原话、修正与验证分开

来源中的命令应保持原样。若提炼过程中发现可能需要修正，必须显示“来源原文”和“建议修正”，不能静默替换。AI 推荐、用户审阅和真实执行不能混成一个状态。

### 用户确认后才进入记录库

AI 可以产生候选草稿，不能直接创建正式记录、覆盖已有记录或改变归属。用户可以删除、合并、拆分和编辑候选。

## 内容模型

### 普通记录

保留现在的快速记录方式。正文仍是唯一必填项，普通想法不需要选择类型、来源或主题。

### 可复用记录

可复用记录仍使用普通 Markdown 正文，只增加可选的用途标识，方便展示和搜索：

- `procedure`：可再次执行的操作；
- `decision`：技术选择及约束；
- `incident`：真实故障、原因和处理；
- `note`：普通记录，默认值。

用途标识不是强制分类，也不决定正文结构。用户随时可以修改或清除。

### 原始素材

原始素材可以是：

- AI 对话；
- 网页或文档片段；
- 分享进来的文本；
- 用户粘贴但尚未决定是否保留的内容。

原始素材与普通记录分开保存和展示。它可以只保留链接和引用片段，也可以在用户明确选择后保存完整快照。

### 提炼自关系

一份素材可以生成多条记录，一条记录也可以引用多份素材。关系只表达来源，不等同于“续写自”。

删除素材不会连带删除已经生成的记录；删除记录也不会删除素材。失去来源后，记录显示“原始材料已删除”，正文仍然可用。

### 验证记录

操作是否可靠通常与环境有关，因此验证应保存为事件，而不是一个永久布尔值：

- 验证时间；
- 环境或设备；
- 执行结果；
- 可选备注；
- 对应的记录 revision。

详情页可以展示最近一次验证，但历史验证不能被新一次验证覆盖。

## 核心用户流程

### 流程一：从分享或粘贴开始

现有分享入口会直接把标题、文本和 URL 合并为一条记录。改版后，分享内容首先进入一份可恢复的本地草稿：

```text
收到一段分享内容

标题：Docker 磁盘空间排查
来源：chat.example.com/...
内容：约 4,200 字，检测到多段对话和 6 个代码块

[提炼可复用内容]  [只保存选中内容]  [直接保存原文]
```

规则：

- 三个动作均由用户显式选择；
- 关闭页面、断网或提炼失败时，分享草稿仍然存在；
- “直接保存原文”应提示它会作为原始素材保存，而不是默认作为普通记录进入时间流；
- 短文本继续允许直接进入快速记录，不增加额外步骤。

### 流程二：选择提炼范围

用户可以决定本次处理的内容范围：

```text
准备提炼以下内容

[✓] 用户提出的问题
[✓] AI 回答
[✓] 后续纠正与补充
[ ] 无关的前置闲聊

将发送约 2,800 字给提炼服务                     [查看全文]
```

如果使用云端 AI，界面必须在调用前展示将发送的准确文本。用户可以返回修改范围，也可以切换为手工提炼。

### 流程三：识别候选记录

系统不直接生成一篇对话摘要，而是先返回候选标题：

```text
找到 3 条可能值得保留的记录

✓ 查看 Docker 磁盘占用并定位大项
✓ 安全清理未使用的 Docker 镜像和缓存
□ 为 Docker 容器配置日志轮转

[重新分析]                                      [继续]
```

用户可以：

- 取消不值得保存的候选；
- 合并必须一起执行的候选；
- 拆开包含多个未来问题的候选；
- 添加一条系统遗漏的候选；
- 在只需要标题判断时停止，不必生成完整草稿。

系统允许返回“没有值得独立保存的内容”。这不是失败，也不应诱导用户为了完成流程而保存无用记录。

### 流程四：检查提炼草稿

每条候选展开为一份可编辑草稿：

```text
查看 Docker 磁盘占用并定位大项

状态       未实际验证
适用环境   Linux；Docker 版本在来源中未说明

什么时候使用
服务器磁盘空间不足，需要判断 Docker 的具体占用来源。

操作
docker system df -v
docker ps --size

验证
docker system df
df -h

风险
以上命令只查看状态。来源同时提到清理命令，但未确认删除影响。

来源       Docker 磁盘管理对话 · 查看对应段落
关键词     Docker、磁盘满、空间不足、system df

[删除草稿] [拆分] [查找相似记录]                 [保存]
```

草稿要求：

- 标题使用“动作 + 对象 + 场景或结果”；
- 缺少环境、版本、回退方法时明确写“未确认”，不自行补全；
- 命令、配置和错误字符串保留原文；
- 需要替换的参数使用可识别的占位符并列出说明；
- 高风险命令单独突出，不与普通代码块混排；
- 新生成的操作记录默认是“未实际验证”；
- 保存前可以查看每个字段对应的来源片段。

### 流程五：更新已有记录

保存候选前，应用使用本地标题、正文和代码搜索已有内容：

```text
可能已经存在相关记录

查看并清理 Docker 磁盘占用
最后更新：2026-05-12 · 已在 Ubuntu 22.04 验证

[查看差异] [更新已有记录] [仍然创建新记录]
```

系统只提示，不自动合并。更新已有记录时仍走 revision 冲突保护，并把本次素材追加为新的来源关系。

### 流程六：真实使用与验证

在操作记录详情页提供“记录一次使用”：

```text
记录一次使用

时间     2026-09-03 14:20
环境     Ubuntu 24.04 / Docker 27 / hk-prod-1
结果     [成功] [部分成功] [失败]
备注     ______________________________

[保存验证]
```

“成功”只代表用户声明在这一环境执行成功，不代表适用于所有环境。记录正文在验证后被编辑时，旧验证仍保留，但界面注明它对应较早的 revision。

## 手工提炼与无 AI 降级

核心数据能力不能依赖 AI。没有配置 AI、处于离线状态或调用失败时，用户仍可以：

1. 在素材中选择一段文字；
2. 点击“整理为操作记录”；
3. 获得一个空的轻量模板；
4. 把命令、场景、环境和验证方法拖入或粘贴到相应位置；
5. 保存记录并保留来源关系。

应用不应因为 AI 失败而删除素材、清空选区或关闭编辑器。失败只影响增强步骤。

用户也可以在其他 AI 中使用 `$conversation-distiller` 得到 Markdown，再粘贴到拾念；应用应正确识别第一行 `# 标题`，不要求专有导入格式。

## 提炼行为约定

内置 AI 提炼应遵守与 `conversation-distiller` 一致的约定：

- 不总结整段对话；
- 只提取可能复用或难以重新构造的内容；
- 按未来独立检索意图拆分；
- 不从常识补充来源中缺失的命令、环境或安全措施；
- 如果提出修正，保留来源原文并明确标记修正；
- 默认使用用户指定语言，否则使用源对话的主要语言；
- 标题和说明可以翻译，命令、标识符、配置键、路径、错误原文及影响检索准确性的技术词保持原样；
- 对疑似密钥、令牌、私钥和口令进行本地提示与遮蔽；
- 不执行任何提炼出的命令。

## 原始素材保留策略

完成提炼时，用户选择来源保留方式：

```text
如何保留原始对话？

● 保存来源链接和引用片段
○ 保存完整对话快照
○ 提炼完成后不保留原文
```

推荐默认值：

- 有稳定 URL 时，保存 URL、标题和被引用片段；
- 没有 URL 时，在用户决定前保留完整本地草稿；
- 只有审计、复杂方案权衡或链接可能失效时，建议保存完整快照；
- 不把完整快照默认加入“最近”时间流。

完整快照属于用户数据，必须进入同步、备份、恢复和 JSON 导出。普通 Markdown 导出中，可复用记录保持独立可读，来源以链接或相对文件引用表示。

## 搜索与找回改版

### 默认结果顺序

搜索结果优先级建议为：

1. 标题精确或近似命中的可复用记录；
2. 命令、配置键或错误原文精确命中的可复用记录；
3. 正文命中的普通记录；
4. 来源标题和引用片段；
5. 完整原始素材。

原始素材仍可搜索，但默认折叠在“原始材料”分类中，避免长对话凭借高词频占据结果。

### 搜索筛选

在现有“全部、图片、代码、来源、冲突”之外，逐步增加：

- 操作；
- 决策；
- 故障；
- 已验证；
- 未验证；
- 原始材料。

这些筛选用于缩小结果，不要求每条普通记录分类。

### 命令结果

当查询命中代码块时，结果直接展示上下文和复制按钮：

```text
查看 Docker 磁盘占用并定位大项
适用：Linux · 未实际验证

docker system df -v                                  [复制]
```

复制只复制原始命令，不自动替换参数，也不执行命令。包含占位符时，复制前提示需要替换的变量。

## 记录详情改版

普通记录详情保持安静。只有存在相关信息时才显示：

```text
类型       操作记录
状态       未实际验证
来源       Docker 磁盘管理对话 · 2 个引用片段
最近验证   暂无

[记录一次使用] [查看来源] [查找相似记录]
```

全局星标仍表示用户认为重要。未来的主题内置顶可以表示“在服务器管理中常用”，两者不需要在本次改版中同时实现。

## 主题功能的新位置

主题从核心功能降为后续聚合层。第一版主题不需要复杂的动态规则和人工排除模型，可以从轻量的人工集合开始。

“服务器管理”主题页未来可以按内容用途展示：

```text
服务器管理

常用操作
  查看 Docker 磁盘占用
  Nginx 证书续期
  新服务器初始化

最近故障与实践
  hk-prod-1 磁盘告警
  NAS 备份恢复演练

相关原始材料
  3 段 AI 对话 · 2 个网页来源
```

主题规则、保存搜索、批量归类和智能主题建议，只有在提炼与搜索流程被真实使用后仍显示必要时再实现。

## 隐私与安全

### 发送前披露

每次云端提炼必须展示：

- 将发送的具体文本；
- 使用的服务；
- 是否包含完整对话还是选中片段；
- 本次调用不会执行其中的命令。

### 本地敏感信息提示

发送前在本地检查常见的访问令牌、私钥块、密码赋值和认证头。发现疑似敏感内容时：

- 默认遮蔽为描述性占位符；
- 显示遮蔽位置；
- 允许用户返回修改；
- 不声称检查能够发现所有秘密。

### 高风险命令

删除、覆盖、防火墙、权限、磁盘和数据库变更等命令应突出显示。产品只展示来源已有的风险说明；AI 补充的安全建议必须标记为建议，不能冒充来源结论。

## 概念数据模型

以下用于明确产品边界，不是最终迁移脚本。

### notes 扩展

- `kind`：note、procedure、decision、incident；
- 现有正文、标题、revision、星标、续写和删除字段保持不变。

### source_materials

- `id` / `sync_id`；
- `kind`：conversation、webpage、text；
- `title`；
- `url`，可空；
- `content`，仅在用户选择保存快照时存在；
- `created_at` / `updated_at` / `deleted_at`；
- `revision`。

### note_source_links

- `note_id`；
- `source_material_id`；
- `excerpt`，可空；
- `source_location`，可空；
- `created_at`。

现有一条记录一个 URL 的 `note_sources` 不足以表达一份素材生成多条记录和一条记录引用多份素材；迁移时应保持旧来源可读并转换为新的来源关系。

### note_verifications

- `id` / `sync_id`；
- `note_id`；
- `note_revision`；
- `verified_at`；
- `environment`；
- `result`：success、partial、failed；
- `comment`。

### topics 与 topic_memberships

- `topics` 只保存主题名称、稳定同步标识和软删除时间；
- `topic_memberships` 关联主题与记录，并保存仅在该主题内生效的 `pinned` 状态；
- 成员关系可移除但不删除原记录，全局星标不受影响。

### distillation_drafts

提炼输入、候选和未保存修改首先保存在 IndexedDB 草稿区。草稿不是服务端权威记录，不进入普通时间流；是否跨设备同步可以在后续根据真实需求决定。

## 同步、冲突与备份

- 正式保存的素材、来源关系、类型和验证事件进入同步队列；
- 记录正文更新继续使用 revision 冲突保护；
- 验证事件采用追加模式，避免设备间互相覆盖；
- 素材正文修改需要独立 revision；
- AI 生成结果只作为草稿，失败或重复响应不能创建重复记录；
- 浏览器完整备份、服务端自动备份和恢复演练必须覆盖新增权威数据；
- 搜索索引和相似度候选都是可重建派生数据。

## 分阶段交付

### 阶段 A：建立可复用记录基础

- 增加可选的记录用途；
- 增加操作记录模板；
- 增加“提炼自”来源关系；
- 分享内容先进入可恢复草稿，不再立即拼成普通记录；
- 支持选中文字手工创建操作记录；
- 搜索增加用途与验证筛选；
- 原始素材不干扰默认结果。

这一阶段不依赖 AI，完成数据模型、离线、同步、备份和导出基础。

### 阶段 B：显式 AI 提炼

- 选择发送范围和调用前预览；
- 候选标题识别；
- 候选拆分、合并和删除；
- 生成可编辑草稿；
- 来源片段追溯；
- 中文优先和技术原文保留；
- 本地敏感信息提示；
- 调用失败完整保留输入。

### 阶段 C：复用与维护

- 保存前查找相似记录；
- 更新已有记录并追加来源；
- 记录实际使用和验证环境；
- 搜索结果直接展示、复制命令；
- 显示验证与 revision 的对应关系。

### 阶段 D：轻量主题

- 手动创建主题；
- 将提炼后的记录加入主题；
- 主题内置顶常用操作；
- 按操作、故障和原始素材分区；
- 根据真实使用情况决定是否增加保存搜索和规则聚合。

## 第一版验收标准

以一段包含解释、三个操作和多个代码块的中文服务器管理对话为例：

1. 分享或粘贴后不会未经确认直接生成一条长记录；
2. 页面关闭、离线或 AI 失败后，原始输入仍可恢复；
3. 用户可以只选择与未来操作有关的段落；
4. 系统按未来问题生成零条或多条候选，而不是一篇摘要；
5. 候选默认使用中文说明，并保留英文命令、配置键、路径和错误原文；
6. 来源未说明的环境、版本、风险或回退方式不会被伪造；
7. 每条新操作记录默认显示“未实际验证”；
8. 用户确认之前不会写入正式记录库；
9. 用户可以查看记录对应的来源片段；
10. 原始对话不会因为词频高而压过标题或命令精确命中的操作记录；
11. 用户可以在没有 AI 的情况下手工完成相同的数据流程；
12. 新增数据经过同步和完整恢复后，来源关系与验证历史保持一致。

## 实现前需要确认的决定

### AI 接入方式

需要确定使用内置服务、用户提供的 API 配置，还是只提供外部 AI 可复制的提炼提示。无论采用哪种方式，数据模型和手工流程都不应依赖单一提供方。

### 原始素材默认保留范围

建议默认保存来源链接和被引用片段，不默认同步完整对话。没有稳定 URL 时，由用户在“保存完整快照”和“提炼后不保留”之间明确选择。

### 用途是元数据还是正文约定

建议使用可选元数据，以支持筛选和差异化展示；Markdown 正文同时保持自解释，保证导出后不依赖拾念才能阅读。

### 验证状态是否进入第一阶段

建议先建立数据结构和“未实际验证”显示，实际验证事件交互放到阶段 C。这样初期保存的 AI 操作不会在以后被误认为已经执行过。

## 推荐的首个实现切片

如果只选择一个足够小、又能改变使用行为的版本，建议实现：

1. 分享长文本先进入草稿；
2. 用户选择“直接保存”或“整理为操作记录”；
3. 手工操作模板包含场景、环境、命令、验证、风险和来源；
4. 记录默认标记“未实际验证”；
5. 原始材料与提炼记录建立来源关系；
6. 搜索可以只看操作记录，并优先命中标题和代码。

这个切片即使没有内置 AI，也已经能配合 `$conversation-distiller` 改善当前流程；之后加入 AI 候选生成时，不需要推翻内容模型。
