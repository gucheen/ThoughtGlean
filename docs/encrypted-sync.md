# 端到端加密同步（Sync v1）

## 边界

拾念在浏览器的 Dexie / IndexedDB 中保存可检索的本地副本；它可以在完全断网时工作。远端**中继**只保存加密操作包，不能收到正文、标题、附件名、笔记 ID、明文时间或搜索索引。

锁定状态不保留同步恢复代码、派生密钥或中继令牌。因此客户端在未解锁时没有请求远端读写的凭据。

这不等于保护已解锁的浏览器、被攻陷的本机系统或用户主动下载的明文备份；这些仍是本地端点安全与备份保管的责任。

## 密钥与配对

创建一个同步库时，客户端生成：

- `vaultId`：128 位随机公开标识；
- 恢复代码：256 位随机秘密，只显示给用户保存；
- `vault token`：通过 HKDF-SHA-256 从恢复代码派生，作为中继访问能力；
- AES-256-GCM 密钥：从同一恢复代码、但不同派生输出得到。

派生的 salt 是 `vaultId`，HKDF info 固定为 `ThoughtGlean encrypted sync v1`。每个操作使用新的 96 位 GCM nonce，并把 `vaultId` 作为附加认证数据。中继数据库仅保存 token 的 SHA-256 哈希和不透明密文；它不会保存恢复代码或 AES 密钥。

新设备需要用户提供中继地址、`vaultId` 和恢复代码。恢复代码丢失且没有已解锁设备时，不能恢复远端内容——这是端到端加密的必要取舍，应与完整本地备份并行保管。

## 中继接口

中继可作为一个单独部署的 ThoughtGlean 实例运行。所有同步接口要求：

```http
Authorization: Bearer <base64url vault token>
X-ThoughtGlean-Vault: <vaultId>
```

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| `POST` | `/api/sync/v1/vaults` | 创建或校验一个 vault；相同密钥可重试。 |
| `POST` | `/api/sync/v1/operations` | 追加最多 100 个密文操作；按 `operationId` 幂等。 |
| `GET` | `/api/sync/v1/operations?after=<cursor>` | 读取游标之后的密文操作。 |
| `GET` | `/api/sync/v1/subscribe?after=<cursor>` | 最多等待 25 秒的新操作；超时后返回当前游标。 |
| `PUT` | `/api/sync/v1/blobs/{blobId}` | 幂等上传一个密文附件 blob。 |
| `GET` | `/api/sync/v1/blobs/{blobId}` | 下载一个密文附件 blob。 |

接口只使用 bearer capability，不使用 Cookie。为让本机应用调用独立域名的中继，它仅对 `/api/sync/v1/` 开放 CORS；其他 API 仍不允许跨域写入。

`thoughtglean` 命令始终以中继角色运行，应为它分配独立 SQLite 数据目录。它只保留 `/api/health` 与上述同步接口；所有 Web UI、本机笔记、附件、Passkey、备份和本机同步接口均返回 `404`。中继应仅经可信 HTTPS 反向代理对外提供，且不得与某一设备的本机库共用数据目录。

## 当前状态与下一步

已实现：浏览器端 Web Crypto 加密会话、内存锁定、可独立部署的盲中继、游标读取、幂等密文追加、加密附件 blob，以及服务端不读取密文的协议测试。

本机笔记与附件各有稳定随机 `syncId`。每个 `vaultId` 使用独立的 IndexedDB 数据库，包含自己的笔记、图片、待传事件和同步游标；首次解锁可把此前的本地库迁入该同步库。同步事件覆盖笔记创建/编辑、软删除/恢复、来源、附件添加/删除及续记关系。客户端仅在同步库解锁后读取该库待传事件：上传前以 AES-GCM 加密，下载后在内存解密并应用到本机库。断网恢复、页面可见、每分钟周期和长轮询订阅都会尝试同步。

冲突规则是保守保留：当同一 `syncId` 的版本无法由时间和版本号安全排序时，远端版本会成为一条可见的“同步冲突”续记，而不是覆盖任一原记录。

浏览器数据库的笔记、续记、来源和附件关系均使用随机字符串主键；中继事件只使用这些跨设备标识，不依赖设备本地自增键。
